The root endpoint `/` confirms the API server is running and reachable. It does not check database connectivity — use [`/health`](/api/health) for a full connectivity check that also verifies the service can handle nickname lookups.

## Request

```http
GET https://hy.star.lat/
```

This endpoint takes no query parameters.

### Example Request

```bash cURL
curl https://hy.star.lat/
```

## Response

A `200` response confirms the server is up. The body contains a `message` field with a human-readable status string and a `meantimeEntertainment` field.

```json Response
{
  "message": "the db will have entries at some point lol",
  "meantimeEntertainment": "https://www.coolmathgames.com/0-papas-freezeria"
}
```

<ResponseField name="message" type="string">
  A human-readable string indicating the server is running and reachable.
</ResponseField>

<ResponseField name="meantimeEntertainment" type="string">
  A URL included in the root response.
</ResponseField>

<Note>
  This endpoint only confirms the server process is alive. For a meaningful health check that also verifies database connectivity, use `GET /health` instead.
</Note>
