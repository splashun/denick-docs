title: "How Denick Caches Nickname Lookups for Fast Responses"

Denick uses an in-memory LRU (Least Recently Used) cache to serve repeated lookups of the same nickname instantly. This keeps response times consistently low even under high traffic, and means most repeat requests are resolved entirely in memory without any additional round-trip overhead.

## Cache Behaviour

<CardGroup cols={3}>
  <Card title="TTL" icon="clock">
    Cache entries expire after **2 hours**. Any lookup for the same nickname within that window is served from the cache.
  </Card>
  <Card title="Capacity" icon="database">
    The cache holds up to **10,000 nickname entries** in memory at once.
  </Card>
  <Card title="Eviction" icon="trash">
    When the 10,000-entry cap is reached, the **least recently used** entry is evicted to make room for the new one.
  </Card>
</CardGroup>

## Cache Invalidation

When nickname data changes — for example because a player changed or dropped their nickname — the corresponding cache entry is **immediately invalidated** automatically. The next request for that nickname is resolved against the latest data rather than the stale cached value.

You do not need to do anything to trigger invalidation. It happens automatically in real time as soon as the underlying nickname data changes.

## What This Means for You

<Note>
  If you look up a nickname and the underlying player data changes shortly afterwards, you may receive the old (stale) data for up to **2 hours** — or until the server-side cache is invalidated for that entry. If accuracy is critical, re-query after the 2-hour TTL window to guarantee you have the latest result.
</Note>

<Tip>
  Implement a short **client-side cache** — for example, a 30-second in-memory map — so your application does not call the Denick API multiple times in rapid succession for the same nickname. Even a brief local cache dramatically reduces your API call volume and keeps you comfortably within the [rate limit](/concepts/rate-limiting) of 100 requests per 60-second window.
</Tip>
